### S5b: Pre-auth and PIN-guess hardening (automated security review of 21b83c2)
- **Status:** Complete (uncommitted)
- Goal: one LAN peer cannot lock the phone out; PIN-guess limits cannot be dodged by rotating IPv6 addresses.
- Acceptance: at most 4 pre-auth sockets per sender inside the global 16 (test: a 5th from the same host refused while another host still connects); throttle key normalises IPv4-mapped IPv6 to IPv4 and buckets IPv6 by /64 (tests: two addresses in one /64 share a lockout; `::ffff:192.0.2.1` and `192.0.2.1` share one); no global lockout (it would let an attacker lock out the owner; stated in spec 3.1); the phone's connect burst is not dropped by the 10/s rate limit (compare the Mac's `allowMessage` exemptions; test with a burst of the phone's startup frames); gate green.
- Notes: `AuthThrottle::sender_key(IpAddr)` replaces the Mac-style `host(endpoint)`: IPv4-mapped IPv6 folds to IPv4 (`to_canonical`), other IPv6 keys as its /64. The same key drives the PIN throttle and `Host::try_pre_auth_slot(sender)`, which now returns `Err(PreAuthRefusal::Full | SenderFull)`; `ConnectionLimits.max_unauthenticated_per_sender` (default `MAX_UNAUTHENTICATED_PER_SENDER` = 4). Refusal log: `refused <peer>: 4 sockets from <key> already waiting for auth (refused=N)`. The loopback-only check also uses `to_canonical`. No global lockout (spec 3.1). Rate limit: the Mac exempts only `auth` and also counts pre-auth frames from a window opened at connect (`WebSocketServer.swift:1295-1305`), so it drops a >10-frame first second too; Windows kept at parity (no new exemption). The phone's listed connect burst is 6 counted frames and passes. The rate-limit log line now names the first dropped type (`(first type=…)`, snake_case only) so the frames behind the S5 simulator drop can be identified on the next QA run.
- Validation: `rtk proxy cargo test` 392 unit + 11 vectors + 57 integration passed; `printf 'QuipWindows/src/lib.rs\n' | tools/check.sh --files -` all green; `cargo mutants --file src/host.rs --file src/services/auth_throttle.rs --file src/services/ws_server.rs -j 4` (QUIP_SHARED_FIXTURES, QUIP_FAKE_WINDOWS_FIXTURE set): 192 tested, 136 caught, 11 missed, 45 unviable; every miss is in code this slice did not change (`AuthThrottle::gc` `>` x3, `ws_config` max_message_size, `spawn` `Ticks::Auto` `==`, `is_benign_close` x5 and its `!` at the call site).

### S5c: Exact-address lockout, /64 only slows guesses (security review of 53879c6)
- **Status:** Complete (uncommitted)
- Goal: S5b keyed the hard lockout and the pre-auth slot cap by /64, so one device on a shared /64 (home LAN, a Tailscale tailnet) can lock out every other device in it. Keep rotation useless without that.
- Acceptance: hard 10-failure lockout and the 4-per-sender pre-auth cap keyed by exact address (IPv4-mapped still folded to IPv4); a separate /64 failure count only adds delay (escalating, capped) and never refuses a correct PIN; tests: two addresses in one /64 do NOT share a lockout and each can still pair with the right PIN; rotating addresses in one /64 gets the growing delay; the 5th pre-auth socket from one exact address is refused while a neighbour in the same /64 connects; spec 3.1 updated; gate green; mutation results on changed files.
- Notes: `auth_throttle::Sender::of(IpAddr)` replaces `AuthThrottle::sender_key`: `address` (canonical IP, mapped IPv4 folded) keys the lockout and `try_pre_auth_slot`; `network` (IPv6 /64, IPv4 = the address) keys a second table that only adds delay. `attempt(&Sender, correct)`: a right PIN from a non-locked address is `Accepted` at once (no delay, no network check); a wrong PIN waits `max(own delay, network_delay_ms(n))`, where `network_delay_ms` is 0 up to 10 network failures (single device keeps the Mac's 200..1800, 0 table) then 200 ms x n capped at `MAX_NETWORK_DELAY_MS` 30 s (n=150); the lockout-starting failure also waits the network delay. The delay is slept before the `Incorrect PIN` reply while the socket holds its pre-auth slot (so throughput is at most 16 guesses per delay). A success does not reset the network count; it is GC'd after 1 h idle. `Host::handle_auth(id, &Sender, pin)`; logs use the exact address. Known trade (accepted by the review): 4 rotated addresses can still fill the global 16 pre-auth slots, as any 4 LAN hosts could.
- Validation: `rtk proxy cargo test` 409 unit + 11 vectors + 59 integration passed; `cargo clippy --all-targets -- -D warnings` clean; `cargo fmt` applied; `printf 'QuipWindows/src/lib.rs\n' | tools/check.sh --files -` all green; `cargo mutants --file src/host.rs --file src/services/auth_throttle.rs --file src/services/ws_server.rs -j 4` (QUIP_SHARED_FIXTURES, QUIP_FAKE_WINDOWS_FIXTURE set): 195 tested, 142 caught, 10 missed, 40 unviable, 3 timeouts (`send_raw`/`send`/`handle_auth` with `()`: tests hang waiting for a reply, that counts as caught); all misses are in code this slice did not change (`gc` lockout `>` x3, `ws_config` max_message_size, `is_benign_close` x5 and its `!`).
