# QA Mode v1.5 — design spec

**Date:** 2026-05-07
**Branch target:** `eb-branch`
**Builds on:** `docs/superpowers/specs/2026-05-07-qa-mode-design.md` (v1)

## Goal

Replace v1's static colored-tile QA panes with live, simultaneous content for both paired windows so the human → terminal → agent → Sim feedback loop is observable on the phone in real time. Tighten the in-QA UI to a focus mode (suppress non-pair chrome). Add accessibility labels and pane position swap as cheap supporting wins.

## Use case (driving design)

Human pairs a Sim with a terminal in QA mode. Terminal hosts an AI agent. Human types instructions to the terminal. Agent acts in the terminal, which drives the Sim (e.g., installs a build, runs a flow). Sim renders the result. Human watches both panes in real time, types next instruction. The Sim is **observation-only** — humans don't tap the Sim through the phone; the agent does, via terminal commands.

## Scope

**In scope (v1.5):**
1. **Live content in both panes simultaneously.** Per-pane terminal text + screenshots. Both refresh on the same cadence Mac uses for the currently-selected window in non-QA mode.
2. **Mode-exclusive UI in QA.** Suppress every chrome tied to non-pair windows (cycle arrows, follow-frontmost auto-pin, spawn-picker, attach-existing, window-id-targeting quick-buttons).
3. **Accessibility labels on grid tiles.** Each `WindowRectangle` exposes a meaningful `accessibilityLabel` (`"Window: <app> – <name or folder>"`).
4. **Pane position swap.** Horizontal swipe across panes already flips selection in v1; v1.5 adds a small "swap" affordance (long-swipe or dedicated chip button) that swaps which window renders left vs right. Selection-swipe stays at 40pt threshold; position-swap uses a separate gesture (see below).

**Out of scope (carries to later):**
- Sim writability via `KeystrokeInjector` — Sim stays read-only in v1.5 too. Use case explicitly does not require it.
- Browser-on-localhost target type — separate codepath, separate brainstorm, ships as v2.
- Multi-pair management — single pair per backend stays the v1.5 limit.
- Refresh-rate boost — keep existing cadence; add later if user reports lag.
- Mac-side debug `simulate_window_closed` — tooling, not a user-facing feature.

## Architecture

### Approach A — per-windowId state map (selected after brainstorm)

iOS extends single-window content state to per-window:

```swift
@State private var terminalContentTextById: [String: String] = [:]
@State private var terminalContentScreenshotById: [String: String] = [:]
@State private var terminalContentURLsById: [String: [String]] = [:]
```

**Mac side:** existing `RequestContent(windowId)` API stays as-is. No new message types. Mac is "pull" — it returns content when iOS asks, indexed by windowId.

**iOS side:**
- Non-QA mode: behavior unchanged. iOS requests content for the *selected* windowId; renders inline below the grid using the content for that windowId.
- QA mode: iOS requests content for **both** pair halves on its refresh tick (same interval Mac uses for non-QA single-window). Each `QAPairLayoutView` pane renders the entry from the maps keyed on its own windowId.

Migration: any existing single-state reads (`terminalContentText`) become reads through the map keyed by `selectedWindowId`. Bind sites already gate on `selectedWindowId != nil` so the map fallback (`map[id] ?? ""`) preserves existing UX.

### Per-pane content rendering

Replace `WindowRectangle` in `QAPairLayoutView.pane(window:)` with a new `QAPairPaneContent` view:

```swift
struct QAPairPaneContent: View {
    let window: WindowState
    let isSelected: Bool
    let text: String?
    let screenshot: String?
    // Renders:
    //   - Header chip (color border, name, subtitle) -- same as WindowRectangle header
    //   - Body: terminal text scroller for terminals OR screenshot for targets
    //   - Selection ring (isSelected -> 2pt blue border)
}
```

Branching by `window.isTarget` vs `window.isTerminal` mirrors the existing `terminalContentView` logic in `MainiOSView` — extract the rendering core out of `terminalContentView` into a private helper that both `MainiOSView` and `QAPairPaneContent` call.

### Refresh cadence

Single shared timer in `MainiOSView` ticks at the existing screenshot/content cadence. In QA mode, the tick fires `RequestContentMessage(windowId:)` for both pair halves in the same dispatch. No per-pane separate timer.

If terminal+sim payloads land at different times (different async paths on Mac), each one updates only its windowId entry in the map; the corresponding pane re-renders independently. No blocking.

### Bandwidth-priority fallback (B/C if A inadequate)

Documented but not implemented in v1.5. If field-testing shows refresh starvation:
- **B**: Mac auto-pushes both halves on Mac-side cadence (new message: `QAPairContent` with both windowIds). Removes iOS pull.
- **C**: Single-state alternating between panes — rejected as flickery.

Skip until measured.

### Mode-exclusive UI

iOS-only. Driven by a single `manager.active.qaPair != nil` predicate already used to switch into QA layout in v1.

In `MainiOSView.body`:

```swift
if let pair = manager.active?.qaPair, /* both windows present */ {
    QAPairLayoutView(...)         // existing v1 view, swap WindowRectangle for QAPairPaneContent
} else {
    // Existing grid + inline content
    // Behavior unchanged from v1
}
```

Suppression points (every site reads the same predicate):
- `cycleWindow(direction:)` — early-return when QA active
- Follow-frontmost auto-pin — gate the `selectedWindowId = newFrontmost` write on `qaPair == nil`
- Spawn-picker / attach-existing buttons — hide when `qaPair != nil`
- Quick-button slots that send `QuickActionMessage(windowId: ...)` to non-pair ids — hide or no-op
- Settings remains accessible (need to be able to leave QA via the xmark already in the chip; settings is a non-window action)

### Accessibility labels on grid tiles

Add `.accessibilityLabel("Window: \(window.app) — \(window.folder ?? window.name)")` and `.accessibilityHint("Long-press for actions including QA pairing")` to `WindowRectangle.body`. Surfaces tiles to VoiceOver and to the `ios-simulator-skill` `screen_mapper.py` script for UI automation.

### Pane position swap

v1 swipe-flip flips selection (read-only side). v1.5 keeps that; adds **position swap** via a long-swipe (≥120pt horizontal, 2:1 H/V) OR a chip button on the header (icon: `arrow.left.arrow.right`).

Pick chip button — gestures already crowded (drag for divider, swipe for selection-flip, long-press for tile menu). Chip button placed left of the existing re-pair button:

```
[xmark]  [arrow.left.arrow.right]  [name chip ⇄ name chip]  [rectangle.split.2x1]
```

Tap → swap which windowId renders in the left vs right pane. Persist swap state alongside `dividerRatio` in `@AppStorage("qaPair.swapped.\(backendId)")`.

## Failure modes / non-functional

- **One pane's content load fails or is slow.** Other pane unaffected. Failed pane shows last-known content + dim ring + small spinner. No global block.
- **Pair lost mid-render.** Existing v1 `qa_pair_lost` flow still works — toast + grid return. No content-related extra handling needed.
- **Mac doesn't yet have content for a window** (e.g., Sim not yet screenshot'd). Pane shows the v1 colored tile fallback until first content arrives. No blank/empty pane.
- **Bandwidth pressure.** Out of scope to actively manage. If users see lag, file follow-up; promotion to B is the response.

## Wire format

**No changes.** v1's `RequestContentMessage(windowId:)` and the existing `TerminalContentMessage` (text + screenshot + URLs) carry both pair halves identically — iOS just sends two requests instead of one.

## Test plan

- **iOS unit**: per-windowId map mutation logic — selecting a different window doesn't smear content across slots; pair-lost clears both slots.
- **iOS unit**: `QAPairPaneContent` renders text for terminals, screenshot for targets, fallback tile when content nil.
- **Mac unit**: no change — existing filter + validator tests cover Mac contract.
- **Hardware smoke** (carry-over from v1):
  - Pair on physical iPhone, agent in terminal triggers Sim render — both panes update live.
  - Type in QA mode → text reaches the *terminal*, never the Sim (read-only stays).
  - Cycle arrows + spawn buttons disappear in QA.
  - Long-press grid tile → context menu (verifies accessibility labels are reachable too).
  - Position-swap chip → panes swap; `dividerRatio` and selection persist across swap.
  - Same v1 recovery cases (window_closed, reconnect-replay, mac-restart) — no regression.

## Build sequence (sketch — full plan via `superpowers:writing-plans`)

1. **A11y labels on `WindowRectangle`** (~30 min, cheap win, zero risk to v1).
2. **Pane position-swap chip button** (~1 hr, additive UI on existing layout).
3. **Per-windowId content state migration** (~2 hr, touches `MainiOSView` state + bind sites).
4. **`QAPairPaneContent` view + `QAPairLayoutView` swap** (~2 hr, factor `terminalContentView` core into shared helper).
5. **Mode-exclusive UI suppression** (~1 hr, audit + gate the listed sites).
6. **Smoke pass on physical iPhone** — verify dual-live content, focus mode, all v1 still passes.

Total estimate: ~6–8 hr of focused work, suitable for one continuous session via `superpowers:subagent-driven-development`.
