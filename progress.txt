## Codebase Patterns
- QuipMac is NATIVE macOS SwiftUI. ALL Settings UI is in QuipMac/Views/SettingsView.swift (sidebar NavigationSplitView; panes General/Layouts/Projects/Prompts/Connection/Security/Notifications, each a grouped Form).
- COMPILE ORACLE: ONLY `xcodebuild build -project QuipMac/QuipMac.xcodeproj -scheme QuipMac -destination 'platform=macOS,name=My Mac' -derivedDataPath build`. IDE/SourceKit "Cannot find type X in scope" + "Generic parameter 'T' could not be inferred" are SPURIOUS cross-file noise — IGNORE them, trust xcodebuild.
- DO NOT install (/Applications), ditto, killall, codesign, open, or touch TCC. DO NOT use dev-browser / any browser (native app). A human installs + verifies visually.
- Reusable components already in SettingsView.swift: StatusDot (kinds ok/bad/warn/neutral/busy = tinted SF-symbol + label), connectionHero (focal status: tinted circle glyph + title3 headline + caption subline), grouped Form, SettingsIconTile, SettingsIdentityHeader, ~600pt detail content cap.
- Preserve ALL logic verbatim (importKey + APNs key-id auto-sync, sendTestPush, QR/pairing share, diagnostics bundle, PIN save/regenerate). Reorganize layout/sections ONLY — no behavior change.
- Stay on eb-branch; never push; git add only QuipMac/Views/SettingsView.swift + prd.json + progress.txt (never -A).
- StatusDot usage: `StatusDot(kind: .ok/.bad/.warn/.neutral/.busy, text: "…", mono: false)`. Renders tinted SF glyph + `.body` text in an HStack(spacing:6). Use it for ANY status indicator — replaces ad-hoc `Image(...).foregroundStyle(.green/.red)` + colored Text. NOTE its text is `.body` font, so when a status row also needs a monospaced path/detail, keep that detail as a separate `.caption.monospaced()` Text below the StatusDot rather than cramming it into `text:`.
- Section grouping convention: every Section gets a `header:` Text (even the first one if it isn't a hero) and pure-info prose goes in a `footer:` (`.font(.caption).foregroundStyle(.secondary)`), never a standalone control-less Section.
